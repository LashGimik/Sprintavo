# Sprintavo

iOS-приложение для управления личными проектами, задачами, заметками и спринтами. Учебный проект для изучения Swift, SwiftUI и проектирования бизнес-логики.

**Статус: прототип в разработке.** Данные хранятся в памяти текущего запуска и исчезают после завершения приложения. Это ещё не релиз 0.1.

## Что работает

- Создание проектов с названием, описанием и цветным значком.
- Переключение между проектами, разделами и вложенными экранами.
- Создание, редактирование и удаление задач.
- Шесть статусов задач, приоритеты и необязательные сроки.
- Поиск, фильтры и сортировка задач внутри проекта.
- Шаги задач с отдельными статусами и редактированием списка.
- Общий поиск по демонстрационным данным и созданным элементам.
- Показ активных и архивных демонстрационных проектов.

Заметки и спринты пока представлены демонстрационными экранами. Архивирование проектов и постоянное хранение ещё не реализованы.

## Стек и структура

Swift, SwiftUI, Observation, MVVM. Исходники сгруппированы по разделам приложения; View и ViewModel расположены рядом. Общее оформление и переиспользуемые элементы находятся в `Appearance`.

```text
Sprintavo/
├── SprintavoApp.swift
├── Main/
├── Projects/
├── Tasks/
├── Notes/
├── Sprints/
├── Search/
├── Models/
├── Appearance/
└── Resources/
```

`WorkspaceItem` — временная модель прототипа. `MainViewModel` управляет общей навигацией и данными в памяти; отдельные модели отвечают за формы, поиск и фильтры.

## Запуск

1. Клонируйте репозиторий и откройте `Sprintavo.xcodeproj` в Xcode.
2. В текущих настройках проекта указан deployment target iOS 27.0. Требуется Xcode с соответствующим SDK.
3. Выберите схему Sprintavo и подходящее устройство или симулятор.
4. Для запуска на физическом устройстве укажите свою команду подписи в Signing & Capabilities.

Внешних зависимостей нет. Основная целевая платформа — iOS; другие платформы, перечисленные в настройках Xcode, отдельно не проверены.

## Работа с репозиторием

`main` хранит проверенное состояние. Новые функции разрабатываются в отдельных ветках, например `feature/local-storage`, и объединяются через Pull Request после проверки приложения. Коммиты описывают отдельные законченные изменения.
